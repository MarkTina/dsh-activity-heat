# activity-heat 插件「重启后不自动加载」诊断与官方规范

> 结论先行：**真正的根因不是加载时序，而是 profile 实际加载的是 `0.7.11` 的旧副本，而不是工作区代码。**
> profile 的 `pnpm-lock.yaml` 把 `@local/activity-heat` 解析成了 GitHub tarball（`bb9ba5f` = 0.7.11），
> 因此工作区 0.7.12–0.7.15 的所有修复都没有进入 DSH 的加载路径。旧 0.7.11 在启动期又会抢占宿主
> single 席位 / 依赖 Harness Client 包而抛错，于是表现为「重启不加载，手动禁用/启用才恢复」。

---

## 1. 官方插件开发规范（随 DSH 发布的手册）

位置（在 `app.asar` 内，随安装包发布）：

- `@deepseek-ai/dsh-agent-preset/skills/cordis-plugin-development/SKILL.md`
- `references/host-plugin.md` — bundle 清单、Host 导出、注册行
- `references/ui-plugin.md` — Web UI：Client 清单、Module Loader、slot 注册
- `references/practices.md` — 扩展点与 UI 红线

### 1.1 注册方式（官方要求）

**① 包是 bundle**：`package.json` 声明 `dsh.bundle.patch`，再由 `cordis.patch.yml` 插入插件行：

```json
{
  "name": "@local/my-plugin",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./index.js", "./client": "./client.js" },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "immediately": true, "inject": ["@deepseek-ai/dsh-client-ui-conversation"] }
  }
}
```

```yaml
# cordis.patch.yml
- insert:
    - id: my-plugin
      name: '@local/my-plugin'
      config: {}
```

**② Host 半侧**：`index.js` 导出 `export function apply(ctx, config) {}`（可选 `export const inject` / `Config`）。

**③ Client 半侧（UI 插件）**：浏览器侧注册一个惰性 factory，**id 必须等于包名**：

```js
window.__ModuleLoader__.load({
  id: '@local/my-plugin',
  factory(require) {
    const React = require('react');
    return {
      inject: ['slots'],
      apply(ctx) {
        ctx.slots.inject('some.slot', () => ctx.slots.register(
          { name: 'some.slot', id: 'my-plugin', order: 5 },
          Component,
        ));
      },
    };
  },
});
```

**④ 官方红线**（`references/practices.md` §UI）：

> Do not `require('@deepseek-ai/dsh-client-ui-primitives')` or load any other Harness Client package as a module … a throwing component blanks your slot entry.

即：**不要 require 任何 Harness Client 包**，UI 组件本地实现 + `--dsw-alias-*` 主题令牌。

**⑤ 启动加载链路**（只要「启用」即自动生效，无需 hack）：

```
profile.dsh.profile.bundles 含该包
  → 加载包内 cordis.patch.yml，插入 Host 插件行
  → Host 扫描 Loader entries 中声明 dsh.client 的包
  → 组装 window.__DSH_BOOT__
  → 浏览器 Module Loader 创建 entry
  → cordis 按 inject:['slots'] 等服务就绪
  → 调用 apply(ctx) → ctx.slots.inject / register
```

## 2. 本次事故的真实根因（证据链）

### 2.1 证据 A：profile 里是实体副本，且版本是 0.7.11

```text
C:\Users\Marktowin\.dsh\profiles\desktop\node_modules\@local\activity-heat
  Attributes : Directory      （不是 Junction/Symlink）
  package.json version : 0.7.11
  client.js 353368 bytes / LastWriteTime 2026-11-04 10:35
```

工作区：

```text
D:\codex-project\dsh-activity-heat
  package.json version : 0.7.15
  client.js 355998 bytes
```

对比关键标记（旧副本 vs 新代码）：

| 标记 | profile 旧副本 0.7.11 | 工作区 0.7.15 |
|---|---|---|
| `require('@deepseek-ai/dsh-client-ui-primitives')` | **有**（违反官方红线） | 无（已移除） |
| 插件级 `inject: ['slots']` | 无 | **有** |
| `shell.bottom priority: -1000` | 无 | **有** |
| `sidebar.toggle.badge` 抢占 | 有 | 已移除 |

### 2.2 证据 B：pnpm 锁文件把它指到了 GitHub 旧提交

`~/.dsh/profiles/desktop/pnpm-lock.yaml`（修复前）：

```yaml
'@local/activity-heat':
  specifier: github:MarkTina/dsh-activity-heat
  version: https://codeload.github.com/MarkTina/dsh-activity-heat/tar.gz/bb9ba5f9c5927de50e03b1549049...
```

`bb9ba5f` 正是 0.7.11 的提交。**所以 pnpm/插件管理器每次安装都会拉取并复制这个旧包**，与工作区无关。

### 2.3 证据 C：`package.json` 写的是 link，但锁/实体目录没跟上

profile `package.json` 里写的是 `"@local/activity-heat": "link:D:/codex-project/dsh-activity-heat"`，
但 `node_modules/@local/activity-heat` 是普通目录（副本），说明安装产物与声明不一致，且锁文件仍指 GitHub。
这就是「改代码 → 重启 → 没变化」的直接原因。

### 2.4 为什么旧 0.7.11 会「重启不加载、开关才恢复」

0.7.11 同时存在两类启动期问题：

1. 抢占宿主 **single** 席位 `sidebar.toggle.badge`（内置 `client-ui-settings-general` 的 `DesktopUpdateBadge` 已占用，priority 0）→ `slots.register` 抛 `single slot ... already has a registration`；
2. `require('@deepseek-ai/dsh-client-ui-primitives')`，官方明确禁止，组件抛错会把整个 slot 条目打空。

这些异常发生在启动的 apply 链路，导致整条插件注册失败；手动「禁用/启用」触发重新 apply，于是又看似恢复。
**但这也只是旧版本的次生问题；不解决「加载的是旧副本」，任何修复都没有意义。**

## 5. 如何判断「这次是否真的生效」

```powershell
# 1) profile 指向必须是 Junction → 工作区
Get-Item "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\@local\activity-heat" |
  Select-Object LinkType,Target

# 2) 版本必须等于工作区
Select-String "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\@local\activity-heat\package.json" -Pattern '"version"'
Select-String "D:\codex-project\dsh-activity-heat\package.json" -Pattern '"version"'

# 3) 锁文件必须是 link
Select-String "$env:USERPROFILE\.dsh\profiles\desktop\pnpm-lock.yaml" -Pattern 'activity-heat' -Context 0,2
```

三个都满足后再重启 DSH；启动后插件应自动出现，无需手动开关。

## 6. 防复发

1. **不要用 GitHub 地址安装本地开发插件**；本地开发一律 `link:<绝对路径>`，并确认锁文件为 `link:`。
2. 每次改完代码先跑第 5 节的三条检查；`node_modules/@local/activity-heat` 必须是 Junction。
3. 发布/正式安装使用官方 `plugin_manager install_bundle`（或 `dsh plugin --profile <p> add link:<dir>`），
   不要手工改 profile 的 `package.json` / `cordis.patch.yml`（官方 SKILL 明确要求）。
4. 改 UI 前读 `references/practices.md`：不 require Harness Client 包、不抢 single 席位、只用主题令牌。
